### Streamlining the Local Git Workflow

To get more comfortable with real-world developer workflows, I cloned the repo to local and spent time setting up a clean local Git pipeline today.

My initial workspace is messy—full of exploratory scripts, raw drafts, and notes that don't belong in a public repo. At first, I considered keeping the blog site in a subfolder and writing an auto-sync script to copy polished files over. But I realized I could keep things even simpler: save the polished posts directly into the repo's `site/_posts/` directory and use a one-line script to push updates to GitHub Pages.

It keeps the commit history clean, eliminates manual copying, and reduces friction so I can focus on building.

---

### Prototyping Tool #1 (First Pass)

With the workflow sorted out, I dove into the first tool for our collaboration. I mapped out the core feature specifications, detailing the exact inputs, calculation logic, and expected user outputs.

After evaluating the technical requirements, I decided a single-page interactive web app using vanilla HTML/CSS/JS is more than sufficient for this stage. No need to over-engineer with complex frameworks when a lightweight stack gets the job done faster.

I spun up a quick prototype to visualize the user flow. The core logic works, giving me a clear picture of the end product. That said, the UI is still far from user-friendly, with plenty of tiny details and micro-interactions that need fixing. But having a tangible working model on Day 1 moves the needle forward.
