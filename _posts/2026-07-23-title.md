### The 80/20 of Git Workflows

To build a solid engineering baseline, I spent time revising the core 80/20 of Git CLI—the essential commands that cover 90% of daily development without getting lost in edge cases.

Here is the quick breakdown I logged for my dev workflow:
* **Repo Setup & Sync:** `git init` and establishing remotes or `git clone`. Using `git push -u origin <branch_name>` for initial branch tracking, followed by standard `push` and `pull`.
* **Staging & History:** Distinguishing between `git add` and `git add -u` (staging tracked files only). Inspecting clean log graphs via `git log --graph --oneline` and using `git checkout` to step back in time.
* **Branching & Merging Strategy:** Understanding when to use fast-forward merges, merge commits (`git merge --no-ff`), and squash merges to keep history readable without losing traceability.
* **Pull Requests & Conflicts:** Handling PR reviews and resolving merge conflicts.

Getting comfortable with these commands directly in the terminal removes friction when shipping code.

### Refining Feature Specs with AI Assistant

On the collaboration front, I spent the day manually revising the feature specification for our first tool. 

My biggest takeaway from this task: **clarity and simplicity win every time.** Complex, bloated feature descriptions confuse ourselves and LLMs alike. 

Instead of letting LLMs blindly generate specs, I used the model strictly as an interactive sounding board:
* Proposed changes and asked the LLM to validate logic gaps.
* Requested counter-suggestions whenever I wasn't sure if an alternative was better.
* Questioned responses whenever something felt off or over-engineered.

After multiple iterative rounds, I ended up with a crisp, well-defined specification covering all necessary core features. The payoff was immediate: the refined spec allowed generating a solid MVP prototype right out of the box, requiring only minor tweaks and cleanups post-generation.
